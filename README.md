# SAST 运维/Linux 组：前两课授课打样

**方案：第一课 100 分钟，第二课 115 分钟；Typst + Touying 投屏，Markdown 供操作与复习。** 每节都留在两小时以内。第一课不装系统，第二课才带学生安装。

这是一版可编辑、可编译的授课样稿，不是已经在真实教室验证过的课程。既有往届仓库 `../SAST-LinuxGroupLessons/` 保持不改。

**请打开校订版 `Lesson01/lesson01.pdf` 与 `Lesson02/lesson02.pdf`。** 目录中的旧 `slides.pdf` 是前一轮初稿：因阅读器占用未覆盖，包含已纠正的内容，不用于授课。`check-*.png` 和 `.preview/` 是内部排版检查材料，不属于交付课件。

## 1. 已确认与待核实的边界

### 用户已确认

- 面向刚入学的新生；笔试接触过 Shell、终端、文件 I/O、简单网络、Git、Markdown、文件魔数、Base64、后端、正则。
- 拆成两次组内课，而不是把所有内容塞进一次两小时课程。
- VMware 主线，特殊设备有备用方案；Ubuntu 24.04 LTS。
- 使用 Typst 演示，不用 PPT；详细操作仍以 Markdown 更便于复制和检索。

### 本样稿的假设（并非用户已确认）

- 第二课学生可自带笔记本；人数、教室网络、助教数量未知。
- 第一课允许只听讲、纸笔参与，不依赖每个人都有 Linux。
- 理想有 1–2 位助教支持装机；没有助教时必须提前做环境检查。
- 讲师有一台已安装的、非生产用 Ubuntu 演示虚拟机；如果没有，课前按手册准备。
- 没有假设可以登录组内生产服务器，也没有把校园镜像站的运维归属当成已核实事实。

**开课前需确认：**人数和助教 / 各架构占比 / 设备可用性 / 虚拟化权限 / 教室网络 / 实际可用课时。它们影响现场分流，不影响当前内容打样。

## 2. 教学目标与裁剪原则

第一课结束：能写一条可协作的问题，画出环境层次，描述观察—修改—验证的闭环。

第二课结束：有一个可用环境，完成可验证的 Shell 小任务，说明如何恢复。

不以“讲完多少命令”为目标。笔试内容是引子，不是假定全班已经掌握。难题留作扩展，不把进度最快的同学当作全班基准。

**暂不讲：**完整 Linux 历史、全量 FHS、权限位细节、Vim 训练、Git 全套、复杂正则、Shell 脚本控制流、SSH 服务部署、容器。它们属于后续课。

## 3. 第一课：100 分钟

主题：**从“报错了”到“我能排查”**。上半场素养，下半场环境认知与演示。

| 时间 | 内容 | 参与方式 / 产出 |
|---|---|---|
| 00–08（8 分） | 介绍本组工作、能力摸底、今天目标 | 举手选择经验层级，不排名 |
| 08–15（7 分） | “Ubuntu 装不上”热身 | 两人列三个追问，收两个回答 |
| 15–28（13 分） | 提问模板、自查、隐私、X–Y | 将泛泛抱怨改为具体信息 |
| 28–36（8 分） | 改写与互评 | 5 分钟改写 + 3 分钟互评 |
| 36–43（7 分） | 文档入口、AI 使用边界 | 读懂而非盲贴命令 |
| 43–50（7 分） | Missing Semester 与后续课程地图 | 只指定一段短阅读 |
| 50–55（5 分） | 休息 | 同时处理个别提问 |
| 55–67（12 分） | Linux 用途、环境层次、发行版 | 解释 Host / Guest / Shell |
| 67–75（8 分） | 南邮镜像站、ISO 与软件源 | 看实际入口，说明验证与架构 |
| 75–88（13 分） | 本地日志小演示、工程习惯 | 先猜输出，再执行；区分组合与原子性 |
| 88–95（7 分） | 离场卡与下节准备 | 收问题、设备信息、分流需求 |
| 95–100（5 分） | 答疑缓冲 | 不引入新主题 |

若现场只剩 90 分钟：省去 AI 单独讨论（减 3 分）、缩短镜像站浏览（减 3 分）、将原子 rename 的机制解释留到课后（减 4 分）。保留提问练习、终端演示、离场卡。

## 4. 第二课：115 分钟

主题：**把 Linux 装进一个可恢复的环境**。

| 时间 | 内容 | 检查点 / 截止策略 |
|---|---|---|
| 00–10（10 分） | 课前准备检查与分流 | A 已就绪 / B 待救援 / C 特殊路线 |
| 10–20（10 分） | 虚拟硬件、架构、安全边界 | CP1：新建 VM、ISO 已校验 |
| 20–35（15 分） | 引导进入安装器、确认磁盘、开始安装 | CP2：安装目标确认，卡点交助教 |
| 35–60（25 分） | 安装与重启窗口 | 讲师用约 10 分钟讲镜像站；余下巡视和休息，不再填满理论 |
| 60–75（15 分） | 登录确认、备份、换源演示、apt 验证 | CP3：未就绪者切换结对/预备环境 |
| 75–95（20 分） | 独立练习：目录、文件、管道、帮助 | 给定输入，预期输出 2 |
| 95–105（10 分） | 保存快照、演示恢复、解释备份差异 | CP4：能说出恢复范围 |
| 105–110（5 分） | 作业说明、离场问题 | 成功与失败都有可提交证据 |
| 110–115（5 分） | 缓冲与后续救援登记 | 不继续全班排个别设备故障 |

**硬截止规则：**60 分钟仍未获得客户机终端，先转结对/预先安排环境完成共同实验。不能“必须全员装好才继续”，也不能在教室临时要求大家购买云服务器。

## 5. 为什么适合用 Typst 演示？

- `.typ` 是文本源码，可审阅、版本管理；Touying 提供分页与演示主题。
- 编译出的 PDF 可离线投屏，不依赖 Node/npm、网页资源或播放时联网。
- 长命令、逐步操作、FAQ 放在 Markdown，不强行把投影页当安装说明书。
- 本稿使用 Touying **0.6.1** 的 Metropolis 主题、16:9。未使用逐条叠层，因此 PDF 实际页与逻辑页一一对应。
- 局限：PDF 不执行终端命令，没有网页交互。现场切到本地 Ubuntu 终端；教师注释放 `teacher-notes.md`，不要把大段讲稿塞进投屏页。

### 编译与放映

在 `2026-LinuxGroup` 目录执行（命令适用于已安装 Typst 的终端）：

```text
typst compile Lesson01/slides.typ Lesson01/lesson01.pdf
typst compile Lesson02/slides.typ Lesson02/lesson02.pdf
```

编辑时可运行：

```text
typst watch Lesson01/slides.typ Lesson01/lesson01.pdf
```

这里已安装并使用 Typst 0.15.1。首次编译需要联网获取固定版本的 Touying 包；缓存后可离线编译。**只播放已生成 PDF 不需要安装 Typst、字体或联网。**

源码字体：Segoe UI + Source Han Sans SC（思源黑体）；代码 JetBrains Mono + Source Han Sans SC。换电脑编辑时安装对应字体，或修改两份文件中的字体设置后重新检查排版。

PDF 全屏用你熟悉的阅读器：例如 Acrobat 的 Ctrl+L 或支持演示模式的其他阅读器；浏览器 F11 只是窗口全屏，不一定是逐页放映。课前验证翻页、缩放、双屏和终端切换，关闭通知。无需为了 PDF 放映再换一整套工具。

## 6. 关键注意事项

1. **提问课不羞辱新人。** RTFM/STFW 不是组内回答的默认礼仪。没有做过的尝试允许写“不会判断”。
2. **不把工具组合叫作原子性。** `&&` 不回滚；幂等与原子操作分开讲。原子替换只作直觉介绍。
3. **系统安装不是下载竞赛。** 课前确定同一个 24.04.x 版本，准备合法离线材料与可信校验清单，不承诺镜像站速度。
4. **Ubuntu 24.04 配置看实物。** 新装系统通常为 deb822；升级系统和特殊镜像可能不同，不盲改 `sources.list`。
5. **不默认关闭安全功能。** VMware 兼容性先核实版本和错误；不为了课堂统一流程要求关闭内核隔离、安全启动或已有 WSL。
6. **ARM 不拿 amd64 硬套。** UTM 用 ARM64；软件源路径也不同。WSL2 支持 systemd，不把它描述成“没有 systemd 的假 Linux”。
7. **更新与安装分开。** 当堂刷新索引，只装必需工具；系统升级放维护窗口，不能无限拖课，也不能永远不更新。
8. **快照不是备份。** 回滚前保存课后笔记；宿主机硬盘损坏会一起丢。
