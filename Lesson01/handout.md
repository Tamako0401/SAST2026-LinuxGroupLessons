## 2. 提问是协作，不是资格考试

《提问的智慧》帮助我们减少沟通成本；《如何像弱智一样提问》使用反例。读它们的方法，不必接受其中所有语气，更不能拿标题称呼同学。

**你可以问基础问题，可以说“我还不知道该提供什么”。** 回答者也应给具体方向，不能用一句 RTFM 代替教学。

### 模板：按需填写，不是强制表格

```text
【目标】最终想完成什么？
【环境】系统、架构、相关软件版本；宿主机还是虚拟机？
【操作】准确命令或界面步骤。
【预期】本来以为什么会发生？
【实际】完整的相关错误文本；图形界面可以截图。
【已尝试】做过什么，分别得到什么结果？没有就写尚未尝试。
【请求】希望得到解释、排查方向，还是对方案的检查？
```

错误日志优先贴文字和代码块。无法复制的启动画面可以拍照，但保证可读。发送之前删除密码、密钥、Token、Cookie、个人信息。不要把整份生产日志贴到公开群聊。

### 提问之前

1. 读错误：文件不存在、权限不足、网络失败不是同一种问题。
2. 查本地帮助：`grep --help`、`man grep`；再查与版本匹配的官方资料。
3. 搜报错原文的关键词，尝试英文关键词，删去私人路径。
4. 缩小问题，一次只改变一个条件。最小复现应保留必要环境。

课上卡住约 3 分钟就举手；课后可以先自查约 15 分钟再求助。时间是本课建议，不是求助门槛。

### X–Y 问题

想识别文件类型（X），却只问“如何取文件名最后三个字符”（Y）。对方不知道你的目标，可能帮你实现了错误方案。

**把最终目标与已尝试办法一起说出来。** 这也接回笔试的文件魔数：扩展名不总是可信的类型依据。

### 使用 AI

可以请 AI 解释报错、提出假设、列出只读检查。仍要核对版本和官方资料；不要复制看不懂的 `sudo`/删除命令，不要提交私密配置。可以这样问：

> 先解释这条命令的每个部分、修改范围和恢复办法。先给只读诊断，不要立即修改系统。

解决后补一句“原因、修复、验证结果”；没解决也保留当前证据，方便下一次接手。

## 5. Linux 放在什么位置？

```text
宿主机：你的电脑与现有操作系统
└─ VMware：虚拟化软件
   └─ Guest：一台虚拟电脑
      └─ Ubuntu：GNU/Linux 发行版
         └─ 终端窗口
            └─ Bash：Shell，解释并执行命令
```

- Linux 是内核；发行版将内核、工具、包管理等组织成可用系统，不一定包含桌面。
- 终端负责交互，Shell 解释命令；通过 SSH 使用的远程 Shell 也不需要本地 Linux 桌面。
- Linux 常见于服务器、开发环境、嵌入式。Windows 和 macOS 也有日志、命令行与自动化，不是二等工具。
- 本组统一 Ubuntu 24.04 LTS 便于复现，不代表要卸掉原系统。裸机/双系统不在第一课操作范围。
- Windows x86_64 主线用 VMware；Apple Silicon 用 ARM64 虚拟机；WSL2 可用于当前阶段的命令行练习。

[南邮镜像站](https://mirrors.njupt.edu.cn/) 提供的安装镜像（ISO）与软件仓库是不同东西。速度和内容以访问时为准，不能承诺任何网络下都“秒下”。

## 6. 从一个小任务理解 Shell

本节不要求有环境。可以先预测结果，下节课亲手完成。

```bash
# 在 Bash 中执行。每次新建目录，避免覆盖已有文件。
lab=$(mktemp -d "$HOME/sast-lab.XXXXXX")
cd "$lab"
printf '%s\n' 200 404 200 500 404 > status.log
cat status.log
grep -x '404' status.log | wc -l
```

最后预期为 `2`。这里每行恰好是一个状态码；`-x` 表示整行匹配。真实访问日志有多个字段，不能直接把 `grep 404` 当成精确的 HTTP 状态码统计方法。

这是课程使用的 **Bash / GNU/Linux 命令**，不是让你粘到 PowerShell 或 Nushell 里直接运行。

### 四个容易混淆的概念

| 概念 | 示例 | 不是哪回事 |
|---|---|---|
| 组合 | `grep ... | wc -l` | 不代表所有步骤有事务保障 |
| 条件执行 | `A && B`：A 返回成功才执行 B | 不会撤销 A 已做的修改 |
| 幂等 | `mkdir -p notes` 重复执行的目录状态相同 | 不是所有命令都可随意重跑 |
| 原子更新 | 同一文件系统内，满足条件的 rename 替换目录项 | 不自动保证多步事务或断电持久性 |

`>` 会先截断目标文件；`>>` 才是追加，但追加也不代表可以无脑重跑。命令越短不等于越安全。

**工程习惯：**先看目标和权限 → 留退路 → 一次一个修改 → 检查退出状态与结果 → 记录。历史记录缺少输出、版本等上下文，也可能带敏感信息，不是完整实验笔记。
