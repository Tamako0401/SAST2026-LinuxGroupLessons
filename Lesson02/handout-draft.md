## 一、Shell 和命令

上次课说过：终端（Terminal）只负责输入输出，真正解释命令的是 **Shell**。Ubuntu 默认的 Shell 是 **Bash**。可以在终端里输入 `echo $SHELL` 验证。

命令提示符（**Prompt**）出现时，表示 Shell 已就绪。提示符通常显示当前用户名、计算机名和当前目录。命令的一般结构：

```text
命令名称 [参数]...
```

命令名称**大小写敏感**（`ls` 不等于 `LS`）；名称与参数之间用空格分隔，空格数量不限。参数的常见写法：

| 类型 | 语法 | 示例 |
|---|---|---|
| 短参数（开关） | `-参数名` | `-a` |
| 带值短参数 | `-参数名 参数值` | `-n 10` |
| 长参数 | `--参数名` | `--all` |
| 带值长参数 | `--参数名=值` | `--block-size=KB` |
| 位置参数 | 操作对象 | `status.log` |

短参数可以合并写：`ls -a -l` 等价于 `ls -al`。注意：**不同程序的参数语法可能完全不同**，用之前先 `--help`。

两个用来体会 Shell 工作方式的小命令：`echo` 把后面的内容原样输出（复读机）；`sleep 3` 空等 3 秒。执行 `sleep 100` 会发现提示符消失了——Shell 在等前台命令结束。此时按 **Ctrl+C** 可以中断它，终端会显示 `^C`（`^` 代表 Ctrl 键）。

高效输入是命令行的基本功，比背命令更重要：

- **Tab 补全**：补全命令名和文件路径；连按两次列出候选项。
- **↑ / ↓**：翻阅历史命令。
- **Ctrl+C**：中断当前命令；**Ctrl+L** 清屏。
- Home / End 跳到行首行尾，Ctrl+←/→ 按单词移动。

## 二、目录、文件和路径

Linux 用**目录**（Directory，相当于 Windows 的"文件夹"）组织文件。与 Windows 的三点核心差异：

| | Linux | Windows |
|---|---|---|
| 分隔符 | `/` | `\` |
| 根 | 唯一根目录 `/` | 每个盘符独立根（`C:\`、`D:\`） |
| 大小写 | 敏感，`File.txt` ≠ `file.txt` | 默认不区分 |

一切从根目录 `/` 出发。你的家目录（**Home Directory**）是 `/home/用户名`，记号 `~`。在家目录里练习一般不会影响系统，**本课所有操作都在家目录下进行**。

**路径**（Path）分两种：以 `/` 开头的是**绝对路径**（与当前位置无关）；否则是**相对路径**，相对于当前工作目录。两个特殊记号：`.` 是当前目录，`..` 是上一级目录。

基础导航命令：

```bash
pwd          # 显示当前工作目录的绝对路径
cd /         # 进入根目录
cd ~         # 回家（cd 不带参数也是回家）
cd -         # 回到上一次所在的目录
ls           # 列出当前目录的内容
ls -a        # 同时显示隐藏内容（. 开头）
ls -l        # 详细列表
ll           # Ubuntu 默认提供的别名，等价于 ls -alF
```

**先预测，再执行**：当前在 `~/a/b/c`，怎样用一条 `cd` 回到 `~/a`？（答案：`cd ../..`。`cd -` 只记住上一次的位置，连续按会在两个目录之间来回切换，它不是"逐级后退按钮"。）

`ll` 输出的每一列依次是：文件类型与权限、硬链接数、所有者、所属组、大小、修改时间、名字。第一列的权限位本次课不展开，下一课细讲。名字后面的 `/` `*` `@` 符号分别表示目录、可执行文件、符号链接（这是 `-F` 参数的效果）。

创建与查看：

```bash
mkdir demo              # 新建目录
mkdir -p a/b/c          # 父目录不存在时一并创建（不带 -p 会报错）
touch a.txt b.txt       # 新建空文件，可以一次多个
cat a.txt               # 输出文件内容，可以一次连接多个
```

**警告**：不要 `cat` 超大文件（终端会被刷爆，卡住按 Ctrl+C），也不要 `cat` 图片、压缩包等二进制文件（会喷出乱码）。查看大文件应该用下一节的 `less`。

有执行权限的程序可以直接用路径运行，例如编译出的程序用 `./main` 运行（这里的 `./` 不能省，原因涉及 PATH 环境变量，后续课讲）。

找文件用 `find`：

```bash
find ~ -name "*.txt"          # 在家目录下找所有 .txt 文件
find . -maxdepth 1 -type d    # 只在当前一层找目录
```

模式串要用引号包起来（原因见第六节的通配符）。

## 三、复制、移动和重命名

```bash
cp 源路径 目标路径        # 复制；复制目录要加 -r
mv 源路径 目标路径        # 移动；同目录下换名就是重命名
```

cp 和 mv 的行为由**目标是否已存在**决定，这张表值得背下来：

| 目标情况 | 结果 |
|---|---|
| 目标是已存在的目录 | 复制/移动到该目录**里面** |
| 目标是已存在的文件 | **覆盖**，不可恢复！ |
| 目标不存在 | 在目标路径创建副本（`-r` 复制的目录也一样） |
| 父目录不存在 | 直接报错，不会自动创建 |

最容易踩的坑：**cp/mv 完全不根据扩展名判断类型**。`cp file.txt /data/new_dir`（new_dir 不存在）得到的是一个**名叫 new_dir 的文件**，不是目录。**先预测，再执行**：`cp -r demo demo.txt`（demo 是目录，demo.txt 不存在）会得到什么？（答案：一个名叫 demo.txt 的**目录**。）

## 四、删除：没有回收站

**`rm` 删除的对象直接从磁盘消失，几乎无法挽救。** 这是本课最重要的一段话。Windows 用户的"删错了去回收站捡"的直觉在 Linux 命令行不成立。

```bash
rm 文件               # 删文件，可以一次多个
rm -i 文件            # 每次删除前询问（推荐养成习惯）
rm -r 目录            # 递归删除目录（不带 -r 删目录会报错）
rm -ri 目录           # 递归 + 逐个询问；内容多时用 -rI（统一问一次）
rmdir 空目录          # 只能删空目录，非空报错
```

`-f`（force）强制执行、不询问、对象不存在也不报错。`rm -rf` 只应在**确认无误**时使用。

三类高危场景，每一个都真实发生过：

1. **多打一个空格**：`rm -rf /home/user/demo` 手滑打成 `rm -rf /home/user /demo`——家目录整个被删光，然后才开始删 /demo。
2. **相对/绝对路径一字之差**：想删当前目录下的 `data`，打成 `rm -rf /data`——服务器上的数据集可能就此消失。
3. **与变量、通配符混用**：见第六节的引号问题。

顺带一提，现代 rm 对 `rm -rf /` 有特判会拒绝执行并报错 `it is dangerous to operate recursively on '/'`——但**不要依赖防线求生**，好习惯是第一道防线：删目录先加 `-i` 或 `-I`；敲绝对路径前停一秒看清楚；不熟悉的命令先 `--help`。

## 五、查看和编辑

小文件用 `cat`，大文件用分页器：

```bash
less access.log        # 分页查看；Space 翻页，↑↓滚动，q 退出
less +/error access.log  # 直接定位到第一个 error
less -N access.log       # 显示行号
head -n 20 access.log    # 看前 20 行（默认 10 行）
tail -n 20 access.log    # 看后 20 行
tail -f access.log       # 持续跟踪文件尾部，看日志神器，Ctrl+C 退出
```

文本编辑器推荐两条路线：

- **nano**（本课作业推荐）：`nano 文件` 打开即编辑，底部常驻快捷键提示，`^` 代表 Ctrl。Ctrl+S 保存，Ctrl+X 退出。结束。
- **vim**：几乎每台 Linux 服务器都有，但上手曲线陡峭——Stack Overflow 上"如何退出 Vim"被浏览了三百多万次。最少必需知识：启动后处于普通模式，按 `i` 进入插入模式才能打字；按 `Esc` 回到普通模式；输入 `:wq` 保存退出，`:q!` 不保存强退。**会退出就算入门**，感兴趣课后自学教程 1.6 节。

## 六、特殊符号

### 通配符（Wildcard）

由 Shell 展开后交给命令处理：`*` 匹配任意数量任意字符，`?` 匹配任意一个字符，`[...]` 匹配括号内的任一字符。

```bash
ls *.txt          # 所有 .txt 文件
rm img_??.png     # img_00.png 到 img_99.png 都可能中招，删之前先 ls 同样的模式！
```

`ls` 一下通配符展开的结果、确认没有误伤，再换成 `rm`，是好习惯。

### 重定向（Redirection）

每个命令默认带着三个标准通道：**stdin（编号 0）**从键盘读入，**stdout（编号 1）**把正常输出写到屏幕，**stderr（编号 2）**把报错也写到屏幕。stdout 和 stderr 是分开的两条路：`>` 只接住 stdout，报错照样出现在终端。想收走报错，用 `2>`；想让报错跟着 stdout 一起走，用 `2>&1`。

```bash
命令 > 文件       # 标准输出写入文件（覆盖原内容！）
命令 >> 文件      # 追加到文件末尾
命令 2> 文件      # 标准错误写入文件
命令 < 文件       # 从文件读入标准输入
```

**先预测，再执行**：连续执行两次 `echo hello > out.txt`，out.txt 里有一行还是两行？（答案：一行，`>` 每次都覆盖。要追加用 `>>`。）

### 命令连接与管道

```bash
命令1 ; 命令2      # 依次执行，不管成败
命令1 && 命令2     # 命令1 成功才执行命令2
命令1 || 命令2     # 命令1 失败才执行命令2
命令1 | 命令2      # 管道：命令1 的输出直接作为命令2 的输入
```

管道（**Pipeline**）是 Linux 哲学的核心：每个程序只做一件事并做好，把文本流当作通用接口，复杂任务由小工具拼接完成。例：看日志的第 26~50 行：

```bash
cat access.log | head -n 50 | tail -n 25
```

### 变量与引号

```bash
os=Ubuntu         # 赋值，等号两侧不能有空格！
echo $os          # 读取，输出 Ubuntu
echo ${os}24.04   # 用花括号与后续文本拼接
unset os          # 删除变量
```

引号的区别是高频考点：

- **单引号**：内容全部按普通字符处理。`echo '*.txt'` 原样输出 `*.txt`。
- **双引号**：大多按普通字符处理，但**变量会展开**。`echo "$os"` 输出 `Ubuntu`。

引号还能把含空格的路径变成整体：`cd 'My Files'`。

**高危示例**：

```bash
path="/home/user/demo a"
rm -rf $path       # 变量展开后被空格裂开，删掉了两个路径！
rm -rf "$path"     # 正确：双引号保证整体
```

建议：**变量被使用时永远用双引号括起来**。想让特殊符号变回普通字符也可以用转义符 `\`，例如 `mkdir My\ Files`；但注意 `touch \*.txt` 创建的文件，删除时同样要转义，掉了 `\` 就会删光目录下所有 .txt 文件。
