# 第二课实验：一个能解释、能验证的小任务

时间约 20 分钟。在 Ubuntu 的 **Bash** 中操作；不是在宿主机 PowerShell 或 Nushell 中运行。VMware、UTM、WSL2 路线使用相同核心实验。

## 1. 认识环境（3 分钟）

```bash
whoami
pwd
cat /etc/os-release
dpkg --print-architecture
```

记录系统版本和架构。VMware 主线预期 Ubuntu 24.04 / amd64；ARM 路线预期 arm64。版本输出可能包含点版本，不能据此误判失败。

`whoami` 的用户名不必公开；共享作业可脱敏。`pwd` 是当前目录，不是所有文件所在位置。

## 2. 创建新实验目录（4 分钟）

下面每行独立输入，遇到错误先停下。`mktemp` 成功才继续 `cd`；不要在目录创建失败后盲目接着执行。

```bash
lab=$(mktemp -d "$HOME/sast-lab.XXXXXX")
cd "$lab"
pwd
printf '%s\n' 200 404 200 500 404 > status.log
cat status.log
```

预期：`pwd` 显示家目录下的新目录，`cat` 输出如下五行：

```text
200
404
200
500
404
```

解释：`printf` 写入文本，`>` 重定向到文件且会截断原文件，因此在新目录中练习。每次重做创建一个新目录，不覆盖原实验。

## 3. 统计与复制（5 分钟）

先在笔记写下预测，再执行：

```bash
grep -x '404' status.log | wc -l
```

预期结果 `2`（不同环境可能有前导空白）。`grep -x` 选出整行恰好为 `404` 的行，`wc -l` 统计换行符。

```bash
cp status.log status.copy
cmp status.log status.copy
echo $?
```

预期：`cmp` 通常无输出，紧跟的 `echo $?` 输出 `0`，表示两个文件相同。不要在二者之间执行其他命令，否则读到的是别的命令的状态。

不是所有“无输出”都代表成功，也不是所有错误都在标准输出中；真实排错要结合错误信息与结果文件。

## 4. 学会找帮助（3 分钟）

```bash
grep --help
man grep
```

`man` 中 `/pattern` 搜索、`n` 下一个、`q` 退出。没安装 man 时先用 `--help`，不要为了便利工具打断实验。

Tab 自动补全，↑ 查历史，Ctrl+C 中断前台命令。不要随意中断正在写系统的安装器/包管理操作。

## 5. 解释失败（2 分钟）

```bash
false && printf '%s\n' 'not printed'
echo $?
```

预期不出现 `not printed`，退出状态为 `1`。`&&` 是条件执行，不会自动撤销已做过的修改。

## 6. 留下可恢复的状态（3 分钟解释，操作见手册）

- VMware：保存基线快照，写清恢复点，记录回滚会丢弃什么。
- UTM/WSL2：按[手册](vm-install-guide.md)选择关机副本/导出等恢复办法。
- 没有成功建环境：结对完成实验，记录本机错误和后续恢复计划，不伪造“已安装”。

笔记另存到不随虚拟机回滚的位置，但不要因此公开敏感文件。未经确认不删除虚拟机、不注销 WSL 发行版。

## 扩展题（可选）

1. 统计 `500`，预期多少？（1）
2. 如果用 `printf '%s\n' 404 >> status.log` 追加一行，统计如何改变？（3）重复运行为什么会继续改变？
3. 给 `status.log` 增加一行 `1404`，为什么 `grep 404` 与 `grep -x 404` 不同？
4. 只讲给同伴听：快照为什么不能代替独立备份？

### 教师验收

每项 0/1 分，共 5 分，重点是反馈，不作新一轮淘汰考试：

1. 能说明系统版本、架构及操作位置。
2. 固定日志输入正确，统计为 2。
3. 能解释管道或退出状态至少一个概念。
4. 有 apt 成功证据，或具体的失败证据和合理下一步。
5. 能说明恢复范围，并保存一份 Markdown 记录。

不同设备路线不扣分；结对者标明分工。不要把环境下载速度作为能力评价。
